# Работа с моками: логины, данные, сценарии

Пока бэкенда нет, приложение работает в режиме моков (`VITE_API_MODE=mock`, он включён по умолчанию). Моки ведут себя как сервер: проверяют пароль и права, возвращают ошибки и сохраняют изменения.

## Роли: как это устроено

В EventPass **один тип аккаунта для всех**. Роль — это не свойство аккаунта, а отношение человека к **конкретному мероприятию** (так решено в макете, заметка «Один аккаунт, права на мероприятие»):

| Роль | Кто это | Как появляется |
| --- | --- | --- |
| **Гость** | не вошёл в аккаунт | — может открыть страницу мероприятия по ссылке и зарегистрироваться без аккаунта |
| **Участник** | у пользователя есть билет на это мероприятие | зарегистрировался на мероприятие |
| **Волонтёр** | может сканировать билеты этого мероприятия | организатор выдал права по email или ID |
| **Организатор** | владелец мероприятия | создал мероприятие |

Администратора платформы в MVP нет — в макетах его экранов нет.

Поэтому один человек может одновременно быть организатором своего митапа, волонтёром на конференции друга и участником хакатона. Так устроен аккаунт Ивана: на **разных** мероприятиях у него разные роли.

**DEV-плашка в шапке** (видна только в режиме моков и при `npm run dev`) показывает, кто вы сейчас:
- гость — «Роль: Гость»;
- на странице мероприятия или в его дашборде / сканере — «Роль здесь: Организатор / Волонтёр / Участник» для этого мероприятия;
- в личном кабинете — сводка «участник: N · волонтёр: N · организатор: N».

## Сценарии

### Гость регистрируется без аккаунта
1. Если вы вошли — выйдите (Профиль → «Выйти» или «Демо» → «Выйти»).
2. Откройте `/e/devfest-2026`, заполните имя, **новую** почту, согласие → «Получить QR-билет».
3. Откроется экран билета с QR и блоком «Сохраните билет в личном кабинете».

Аккаунт на эту почту создаётся автоматически, но **без пароля**: в реальной системе пароль задаётся по ссылке из письма. Чтобы войти под этой почтой в моках, нажмите «Перейти в личный кабинет» (или «Регистрация») и укажите ту же почту и новый пароль — аккаунт «дозаведётся» вместе с билетом.

### Гость вводит почту существующего аккаунта
1. Выйдите, откройте `/e/devfest-2026`.
2. Укажите почту `ivan@example.com` → «Получить QR-билет».
3. Откроется «Вход» с жёлтой плашкой «У вас уже есть аккаунт». Введите пароль `password`: регистрация завершится сама, откроется билет.

### Участник
Войдите как Иван → «Мои билеты»: QR сразу на экране, «Показать QR на весь экран», «Скачать PDF» (печатная версия), «Отменить регистрацию», вкладка «Прошедшие» (Посещено / Не пришёл / Отменён).

### Волонтёр — сканер
1. Иван → «Мои мероприятия» → вкладка «Волонтёр» → «Открыть сканер».
2. Под полем ввода есть **«Демо-коды»**:
   - активный билет → «Проход разрешён» (повторное сканирование того же кода → «Билет уже использован»);
   - «уже прошёл» → «Билет уже использован»;
   - «отменён» и `EVT-000000` → «Билет недействителен».
3. Можно ввести номер вручную, например `EVT-849102` (билет Ивана на «IT & Data Science 2025»).

Камера распознаёт QR в Chrome и Edge. QR из «Моих билетов» на другом устройстве тоже подойдёт.

### Организатор
1. Иван → «Мои мероприятия» → «Организую»: дашборд, ссылка, сканер, «Редактировать».
2. «Создать событие» → заполните форму, добавьте вопросы → «Опубликовать мероприятие» → экран со ссылкой. «Сохранить черновик» отправит событие во вкладку «Черновики».
3. Дашборд «Всероссийской конференции»: 242 / 250, явка 184, поиск по участникам, «Экспорт в Excel» (CSV).
4. «Добавить волонтёра» → введите `alexey@example.com` или ID `517204` → «Выдать права». Войдите как Алексей: мероприятие появится у него во вкладке «Волонтёр».

### Нет прав
Войдите как Алексей и откройте `/events/e_conf/dashboard` — чужой дашборд: появится уведомление и переход в «Мои мероприятия».

## Где хранятся данные и как их сбросить

- Все изменения (регистрации, сканирования, новые мероприятия, аккаунты) лежат в `localStorage` браузера под ключом `eventpass.mockdb`. Сессия — под ключом `eventpass.token`.
- Данные **у каждого браузера и адреса свои**: `localhost:5173` и `127.0.0.1:5173` — это разные хранилища, в инкогнито тоже всё с нуля.
- Сбросить к исходным данным: «Демо» → **«Сбросить демо-данные»**. Или в DevTools → Application → Local Storage удалить `eventpass.mockdb`.

## Если не получается войти

1. Проверьте, что пароль — `password` (без пробелов, латиницей).
2. Если аккаунт удалили через Профиль → «Удалить аккаунт», он пропал из моков: нажмите «Демо» → «Сбросить демо-данные».
3. Почта, на которую регистрировались гостем, создаётся без пароля — см. сценарий «Гость регистрируется без аккаунта».

## Настройки моков

В `.env` (или `.env.local`):

```env
VITE_API_MODE=mock     # http — настоящий бэкенд, см. BACKEND_INTEGRATION.md
VITE_MOCK_DELAY=350    # задержка «сети» в мс; 0 — без задержки
```

Исходные данные — `src/api/mock/seed.ts`, логика «сервера» — `src/api/mock/mockApi.ts`, список тестовых аккаунтов — `src/api/mock/demoAccounts.ts`. После правки `seed.ts` увеличьте `DB_VERSION` в `src/api/mock/db.ts`, чтобы у всех пересоздались данные.
