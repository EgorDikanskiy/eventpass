# Архитектура

## Слои

```
pages/ ──► features/ ──► api/ (index.ts → mock | http)
  │            │
  └──► shared/ui, widgets/, layouts/
```

| Слой | За что отвечает | Чего не делает |
| --- | --- | --- |
| `api/` | Контракт `Api`, типы, две реализации (моки и HTTP), ошибки `ApiError`, хранение токена | Не знает про React |
| `features/` | Хуки TanStack Query: запросы, мутации, ключи кэша и их инвалидация | Не рисует UI |
| `pages/` | Экраны: собирают UI из компонентов и хуков, обрабатывают формы | Не вызывают `fetch` напрямую |
| `shared/ui/` | UI-кит из макета, без бизнес-логики | Не ходят в API |
| `app/` | Провайдеры, роутер, защита маршрутов, сессия | — |

Главное правило: **страницы работают только с `features/` и типами из `api/`**. Поэтому замена моков на бэкенд не затрагивает экраны.

## Данные и состояние

- **Серверные данные** — TanStack Query. Ключи кэша в `features/queryKeys.ts`. После мутаций инвалидируются нужные ключи (например, после сканирования — сканер и дашборд организатора).
- **Сессия** — `app/AuthProvider.tsx`. Токен лежит в `localStorage`, профиль — в кэше Query под ключом `me`. При ответе 401 (`UNAUTHORIZED`) сессия сбрасывается, и `RequireAuth` отправляет на вход.
- **Локальное состояние** — `useState` в компонентах (формы, выбранная вкладка). Вкладки и выбранный билет хранятся в URL (`?tab=past`, `?ticket=…`), чтобы ссылкой можно было поделиться и работала кнопка «Назад».
- «Реальное время» на дашборде сейчас — опрос раз в 10 секунд (`refetchInterval`). При появлении WebSocket/SSE на бэкенде достаточно в обработчике события вызвать `queryClient.invalidateQueries(queryKeys.stats(id))`.

## Права доступа

Модель из макета: **один аккаунт для всех**, роли — не тип аккаунта, а отношение к конкретному мероприятию.

- участник — у пользователя есть билет;
- организатор — пользователь создал мероприятие;
- волонтёр — организатор выдал права на сканирование.

На фронте права не вычисляются — их проверяет сервер (в моках — `mockApi.ts`, функции `requireOrganizer`, `requireScannerAccess`). Если сервер ответил `FORBIDDEN`/`NOT_FOUND`, экран показывает уведомление и уводит в «Мои мероприятия» (`ForbiddenRedirect`). Так же отрабатывает отзыв прав у волонтёра с открытым сканером.

## Ошибки

Все ошибки API приводятся к `ApiError` с полем `code` (`api/errors.ts`). Компоненты ветвятся по коду, а не по тексту:

| code | Где обрабатывается |
| --- | --- |
| `EMAIL_TAKEN` | регистрация гостя → экран входа с сохранёнными ответами |
| `VALIDATION` + `fields` | подсветка полей формы |
| `UNAUTHORIZED` | сброс сессии → вход |
| `FORBIDDEN` | уход в «Мои мероприятия» |
| `ALREADY_REGISTERED` | после входа просто открываются билеты |

## Стили

- Все цвета, радиусы и шрифты — CSS-переменные в `styles/tokens.css` (значения из UI-кита макета). В модулях не пишем «сырые» цвета, кроме редких полупрозрачных оттенков.
- Каждый компонент — свой `*.module.css` рядом.
- Вёрстка desktop-first (1280). На узких экранах колонки складываются в одну, навигация в шапке переносится второй строкой — отдельной мобильной версии в MVP нет.

## Как добавить экран

1. Если нужны новые данные — добавить метод в `api/contract.ts`, реализовать в `mock/mockApi.ts` и `http/httpApi.ts`, описать эндпоинт в `docs/API.md`.
2. Добавить хук в `features/<домен>.ts` и ключ в `queryKeys.ts`.
3. Создать страницу в `pages/<раздел>/` и маршрут в `app/router.tsx` (внутри `RequireAuth`, если экран закрытый).
